# How to contribute

New here? [Quickstart](../getting-started/quickstart.md) gets you building in
five minutes. This page is what happens after that.

## Pick something

* **[Roadmap](roadmap.md)** — the tasks we know need doing, sized.
* **[`good first issue`](https://github.com/OGRoute/danfo-contracts/labels/good%20first%20issue)** —
  scoped so that no protocol judgement is required.
* **[Threat model → Open problems](../protocol/threat-model.md#open-problems)** —
  the genuinely hard ones. Open a discussion before writing code on these.

Comment on the issue before you start, and wait to be assigned. Two people
solving the same issue wastes one of them, and during a
[Wave](drips-wave.md) that is a whole cycle lost.

## The loop

```bash
git checkout -b registry/bound-summary-length

# ... change code and tests ...

cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Branch names follow `scope/short-description`, with scopes `registry`,
`rewards`, `ci`, `deploy`, `docs`.

Commits are [Conventional Commits](https://www.conventionalcommits.org/) —
`type(scope): description` — one logical change per commit:

```
feat(registry): bound route_id and summary length
test(rewards): cover claim against a pending correction
docs(protocol): document the tie-rejects rule
```

## What review looks for

The [pull request template](https://github.com/OGRoute/danfo-contracts/blob/main/.github/PULL_REQUEST_TEMPLATE.md)
is the checklist, and it is not decoration. In order of how often it comes up:

1. **Every new error path has a test.** `#[should_panic(expected = "Error(Contract, #N)")]`.
   A new error variant without a test does not merge.
2. **Every public function has a `///` doc** naming what it does, who must
   authorise it, and which errors it raises. Look at any existing function for
   the shape.
3. **Every state change emits an event.** The indexer reads events, so a silent
   write is invisible to the application layer.
4. **Every persistent write extends TTL.** Soroban state expires. Use the
   `bump` helper in the registry; a missing bump is a bug that surfaces 30 days
   later, in production.
5. **No `unwrap()` or `expect()` in contract code.** Use
   `unwrap_or_else(|| panic_with_error!(&env, Error::Something))` so callers
   get a typed error instead of an opaque trap. Tests may `unwrap()` freely.
6. **No floats.** Amounts are `i128` in base units.

## What not to do

* **Don't add speculative functions.** Every public function should map to a
  user flow that exists. If you cannot name the caller, it does not belong.
* **Don't change the layout of a deployed `#[contracttype]`** without a
  migration plan in the PR description.
* **Don't renumber `Error` discriminants.** Clients match on the integer. Add
  at the end.
* **Don't commit secrets, `.stellar/`, or `target/`.**
* **Don't open a public issue for a security vulnerability** — follow
  [SECURITY.md](https://github.com/OGRoute/danfo-contracts/blob/main/SECURITY.md).

## Docs count

Changing public behaviour means changing the page that documents it. The
[reference](../reference/registry.md) pages are generated by hand from the
contract source, so they drift unless a PR keeps them honest. A docs-only PR
is a welcome contribution in its own right.

## Conduct

Participation is governed by the
[Code of Conduct](https://github.com/OGRoute/danfo-contracts/blob/main/CODE_OF_CONDUCT.md).
Because this repository takes part in incentivised contribution programmes, it
also treats reward-farming — cosmetic churn, unexplainable generated code,
sock-puppet accounts — as a conduct violation rather than merely a bad patch.
